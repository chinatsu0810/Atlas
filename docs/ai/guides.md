# 国・地域別まとめ（ガイド編集部）

`/places/国/地域/テーマ` のページ上部に出す「まとめ」を、AI社員が作り、会長が確認・手直しして公開するしくみ。

入口は Atlas Office（`/office`）の「国・地域別まとめ室」。運営画面は `/ai/guides`（国・地域別まとめ作成）。
オフィスでは、いちばん新しく更新したまとめの進み具合を、ガイド編集部の5人の状態として表示する（`lib/office/guide-team.ts`）。

## まとめの形

ページには、次の4つの部品で表示する（`components/places/guide-summary.tsx`。見え方の確認用に `/mock/guide-preview`）。

1. **まず知っておきたいこと**：全体に関わる前提（2〜4個）
2. **比べるカード**：選択肢ごとに1枚。すべてのカードが同じ項目を同じ順で持つ。分からない項目は「—」。「公式サイト」ボタン付き。比べるものが無いテーマでは出さない
3. **テーマ別の情報**：「費用」「入学・編入」などの見出しごとのカード
4. **出典**：発信元の種類（大使館・公的機関・学校公式など）ごとに並べ、各項目の番号とつなぐ

## 流れ

| 段階 | 担当 | 内容 |
|---|---|---|
| 企画 | ヘンシュウ（`guide-chief`） | 比べるカードの選択肢（3つまで）と項目（4〜5つ）、テーマ別の見出し（2〜3個）と調べる問いを決める |
| 企画の確認 | 会長（運営画面） | 選択肢・項目・見出し・問いを直接直して「この企画で調査を始める」。またはコメントを付けて企画し直してもらう |
| 調査 | シラベ（`guide-researcher`） | Web検索（最大7回）で、比べるカードの表・テーマ別の問い・全体の前提を調べ、1つずつ出典URLを付けて集める。根拠として引用された部分も出典ごとに取っておく |
| 正誤チェック | タシカ（`guide-fact-checker`） | まず調査のときの引用部分と照らし合わせる（ページは開かない）。確かめられなかったものだけ、出典のページを開く（最大5ページ・1ページ8千トークン） |
| 執筆 | マトメ（`guide-writer`） | 確認済みの情報だけで、4つの部品の形に書く |
| 審査 | チュウリツ（`guide-reviewer`） | 判断の代行・調べた過程の記述・カードの書き方の不揃い・出典漏れ・特定の施設の持ち上げ・個人情報がないかを見る。不合格なら執筆に1回だけ差し戻す |
| 本文の確認 | 会長（運営画面） | 文言の修正、項目・カードの削除、出典の付け外し、リンクの追加、「公式サイト」ボタンの行き先の変更。差し戻し（執筆／調査／企画から）もできる |
| 公開 | 会長の操作 | 下書きを公開版として保存する。テーマのページに、いちばん新しく公開したものが出る |

- 公開は必ず会長の操作で行う。AI社員は公開しない。
- 公開後に手直ししても、「保存して公開し直す」を押すまでページは変わらない。

## 出典の扱い（プログラム側で強制していること）

- 調査の出典は、**Web検索・取得で実際に返ってきたURLだけ**。それ以外のURLを書いた情報は捨てる（`keepVerifiableFacts`。捨てた数は運営画面に出る）。
- 執筆では、正誤チェックで「確認済み」の情報だけを渡す。出典に結びつかない項目は落とす（`toGuideContent`）。
- 会長の手直しでも、出典の無い項目は保存しない。
- **読者向けの文章に、調べた過程を書かせない**（「今回」「確認できた範囲」「記載を確認できませんでした」など）。全員の原則（`lib/ai/guides/prompt.ts`）と審査で止めたうえで、
  執筆結果にそうした言い回しが残っていれば、保存前に項目を落とし、見出しの「（今回確認できた範囲）」のような付け足しを外す（`hasProcessTalk`）。
- 比べるカードは、企画の選択肢の順・項目の順にそろえ直す。中身の無い選択肢は出さず、2つ以上そろわなければカード自体を出さない。

## 実行のしかた

Web検索を含むと全体で数分かかり、1回のリクエストの時間制限に当たるおそれがあるため、
**1回の呼び出しで1段階だけ進める**（`advancePlaceGuide`）。運営画面を開いている間、画面が会長の確認待ちまで繰り返し呼ぶ。

- 同時に2回動かないよう、実行中は `running_since` を立てる。10分たっても消えていなければ、止まったとみなしてやり直せる。
- 失敗したら段階は進めず、`error` に理由を残す。運営画面の「この段階をやり直す」で、同じ段階から再実行する。

## 費用

Web検索は1回ごとに課金される（従量課金）。加えて、検索結果・取得したページをAIが読む分の通常の利用料がかかる。

- 上限は `lib/ai/workflows/place-guide.ts` の `MAX_SEARCHES`（検索7回）/ `MAX_FETCHES`（開くページ5件）/ `FETCH_CONTENT_TOKENS`（1ページ8千トークン）。
  思考の深さ（effort）は `EFFORT`（medium）。Web検索の「続きから再開」は `lib/ai/core/web-skill.ts` の `MAX_CONTINUATIONS`（2回）。
- 検索は1回ごとに、それまでの検索結果をすべて読み直すため、回数に対して読む量はほぼ2乗で増える（検索12回の最初の1本は、企画と調査だけで約85万トークンだった）。
- **1本あたりの予算**は `lib/ai/guides/types.ts` の `TOKEN_BUDGET_PER_GUIDE`（30万トークン。読んだ量＋書いた量）。
  超えたら自動では進めず、運営画面の「予算を超えて続ける」で1段階ずつ進める。段階の途中では止めないので、1段階分は超えることがある。
- 段階を1回実行するごとに、AI呼び出しの使用量を `usage` 列に追記する（失敗した段階でも、呼んだ分は記録する）。
  運営画面に「この1本の費用の目安」として、段階ごとの内訳とともに円で出す。
- 費用は公開価格から計算した目安（`lib/ai/core/usage.ts`。価格が変わったらここを直す）。正確な請求額は Anthropic の管理画面（Usage / Cost）で確認する。
