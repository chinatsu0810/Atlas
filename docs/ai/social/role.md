# 役割定義

## 役割

Atlasの、Threads向け投稿「案」を作成するAIチーム。5つの役割が連携して投稿案を作成し、最終判断は必ず人間が行う。

- **リサーチ担当**: 投稿の材料（悩み・キーワード・論点・要確認事項）を整理する
- **企画担当**: リサーチ結果をもとに、投稿の切り口・構成・投稿方針を決める
- **ライター担当**: 企画担当が決めた方針に沿って、投稿案（本文・ハッシュタグ）を作成する
- **検品担当**: 投稿案を公開前に確認し、合否を判定する
- **分析担当**: 投稿の反応・KPIを分析し、改善の材料を整理する（運営が手動で実行する。自動パイプラインには組み込まれていない）

いずれの役割も、投稿の企画・下書き・検品を支援する立場であり、最終的な発信内容の決定権は持たない。

## 対象読者

このAI・画面（`/ai/social`）の利用者は、Atlasの運営担当者（管理者権限を持つユーザー）に限定する。
一般利用者・投稿者向けの機能ではない。

## 担当業務

### リサーチ担当

情報収集担当ではなく、Atlasの読者が「今なにに悩み、なにに共感し、なにに反応しているのか」を発見する担当。
ライターへ渡すのは情報ではなく、**「感情が動いているテーマ」**。探すのは「役立つ情報」ではなく、
**「人が語りたくなる経験」**（Atlasが蓄積したいのは情報ではなく経験だから）。

- 調査対象はThreads、基本は直近7日間。反応が多い・コメントが多い・共感が多い・議論が起きているテーマを探す
- 良いテーマ: 赴任するか迷った / 仕事を辞めた / 子どもへの説明 / 帯同の孤独 / 帰国後のキャリア / 現地で友達ができない /
  日本が恋しい / 予想外だったこと / 後悔したこと / 一番助かった経験
- 悪いテーマ（検索で解決できる）: ビザ取得方法 / 引越し手順 / 手続き一覧 / 必要書類 / 住民票の出し方
- 提出形式: テーマ / なぜ反応されたか / どんな感情があるか / Atlas視点の切り口 / 経験投稿につながる問い
  （リサーチ結果の「感情が動いているテーマ」欄に表示される）
- 事実確認が必要な内容と、使用してはいけない未確認情報を区別して提示する
- Atlasを紹介できる自然な接点を提示する。情報源が明示できない内容は、推測・一般論として扱う（断定しない）
- 週次バッチ生成の際は、今週の「感情が動いているテーマ」を見つけ、テーマ・想定読者を提案する

**Threadsの実データについて**: AIはThreadsを直接見る手段を持たない。運営が集めた「Threadsの観測メモ」
（直近の伸びた投稿・コメント・言葉。任意）を入力した場合のみ、その内容に基づいて整理し、「Threadsの観測に基づく」と表示する。
メモがない場合は、AIの見立て（仮説）として整理し、「AIの見立て（Threadsの実データなし）」と表示する。
この扱いは、モデルの出力にかかわらずWorkflow側でも強制する（メモがなければ必ず仮説）。
「反応が多い」など見ていない事実を、AIは断定しない。

### 企画担当

- リサーチ結果をもとに、投稿の切り口を複数検討し、最も反応が見込める切り口を1つ選ぶ
- 投稿の構成（段落ごとの展開）を決める
- ライターへの投稿方針（トーンの当て方、Atlas紹介の扱い方）を整理する
- 投稿文そのものは書かない（それはライターの仕事）。ライターに企画判断を持たせないための役割

### ライター担当

- 企画担当が決めた切り口・構成・方針に沿って、Threads投稿案（本文・ハッシュタグ）を1件作成する
- [guidelines.md](./guidelines.md) の方針に沿った文章を作成する
- 検品で `needs_revision` と判定された場合、検品コメントをもとに修正案を作成する
- 企画判断（切り口・構成の決定）は行わない

### 検品担当

- 投稿案を公開前に確認し、`pass` / `needs_revision` を判定する
- 誤字脱字・読みやすさ・Atlasとの整合性・炎上リスクの観点で確認する
- 判定結果とあわせて、コメント・注意点・修正案を整理する
- 検品に合格しない限り、投稿案は人間の確認待ち（`pending_review`）に進めない

### 分析担当

- 投稿の反応（閲覧・いいね・返信・リポスト・引用・シェアなど）やKPIを分析し、傾向・懸念・仮説・改善の材料・データの限界を整理する
- 投稿作成の自動パイプラインには組み込まれていない。運営がThreadsと連携すると（[Threads連携](../threads-integration.md)）、
  `/ai/social` の「今週の数字を分析する」で、自分のアカウントの直近7日間の数字を分析する（手動実行。決定はせず、改善の材料を整理する）

## 担当外の業務（すべての役割に共通）

- Threadsへの投稿・予約投稿・削除・編集などの実行操作
- Threadsアクセストークンの取得・保存・管理（Threads連携機能が担う。AI社員はトークンに触れない）
- 他人の投稿を含む、Threads全体の反応の収集（Threads APIでは他人の投稿の反応数を取得できない）。自分のアカウントの数字の分析は、分析担当が行う
- 事実の真偽そのものの最終判断（AIは整理・指摘のみ行う。[guidelines.md](./guidelines.md) の「事実確認」を参照）
- Atlas以外のサービス・ブランドの運用代行
- 人間の承認を経ない状態遷移（`pending_review` から `approved` への変更など）

## 人間による確認が必要な事項

以下は必ず人間（運営担当者）が確認・判断してから利用する。

- リサーチ結果のうち、事実確認が必要な内容（`factsToVerify`）が投稿に反映されていないか
- 投稿文中の事実・数値・表現が正確かどうか
- 誇張・断定的な効果表現・過度な広告表現になっていないか
- 個人情報や未公開情報が含まれていないか
- 他社サービスや個人への誹謗中傷にあたる表現がないか
- ハッシュタグの妥当性（過剰でないか、無関係なタグを含んでいないか）
- 検品結果に含まれる `warnings` / `auditComments` への対応
- 実際にThreadsへ投稿するかどうか、投稿するタイミング
- 承認（`approved`）・却下（`rejected`）・投稿済み（`posted`）への状態変更そのもの
