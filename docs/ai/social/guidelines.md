# 投稿作成ガイドライン

Threads投稿を書くのは、SNS運用担当ではなく、**Atlasの思想を伝える編集者**。
AIへの指示は、人格（`lib/ai/employees/social-writer.ts`）と作業指示（`lib/ai/skills/thread-writing.ts`）に反映している。
ケンピン（`thread-quality-check.ts`）も、このガイドラインを守れているかを確認する。

## Atlasとは

- Atlasはノウハウサイトではない。検索すれば見つかる制度や手続きを説明する場所でもない
- Atlasが扱うのは「実際どうだったか」
- 経験はその人だけの思い出ではなく、未来の誰かを助ける知識。Atlasはその経験を蓄積する場所
- 制度は検索できる。経験は検索できない。経験者の話には、検索では見つからない情報がある

## 投稿の目的

Atlasの目的はアクセス数を増やすことではない。次のように思う人を増やすこと。

- 経験には価値がある
- 経験を残す意味がある
- 経験者に聞く価値がある
- Atlasを使ってみたい

投稿を読んだ人に「勉強になった」と思わせることが目的ではない。理想は、

- それ知りたい
- 経験者に聞いてみたい
- 私も経験を残したい
- Atlasを見てみよう

と思ってもらうこと。

## 投稿で優先するもの

1. 経験
2. 共感
3. 気づき
4. Atlasの思想
5. ノウハウ

**ノウハウは最後。**

## 投稿文字数

- 推奨: 150〜300文字
- 上限: 500文字（**ハッシュタグを含めた全体**で数える）
- 500文字を超える場合は削る。Threadsは記事ではなく、全部を伝える必要はない。興味を持たせることを優先する
- 上限は、ケンピンの判定にかかわらずWorkflow側でも強制する（超過した投稿案は必ず差し戻し）。
  画面の文字数表示も、ハッシュタグ込みで上限を超えると赤く表示される

## 最初の1文が最重要

タイムラインでは最初の1文しか見られない。最初の1文でスクロールを止める。説明から始めない。

良い例:

- 正直、一番大変だったのは英語じゃなかった。
- 赴任前に知りたかったことは検索しても出てこなかった。
- 30記事読んだのに、一人の経験談が一番役に立った。
- 「それ先に言ってよ」と思ったことがある。
- 海外赴任が決まった日から、同じ検索を何度も繰り返した。

悪い例:

- 海外赴任が決まったらやること
- 駐在準備の流れ
- 海外生活で大切なこと
- 今日は〇〇について解説します
- ①②③④形式の説明

## 書いてはいけない投稿

- 手順解説 / チェックリスト / 網羅的説明 / マニュアル化
- AIっぽい整理された文章 / ブログ記事の要約
- 箇条書き中心の構成 / 制度説明だけの投稿

## 書くべきテーマ

- 実際に困ったこと / 意外だったこと / 検索では出てこなかったこと
- 失敗談 / 後悔したこと / 助かった経験
- 当事者しか分からないこと / 帰国後に思うこと / 子育てや生活のリアル

週次バッチのテーマ選定（`thread-topic-planning.ts`）とリサーチ（`thread-research.ts`）、企画（`thread-planning.ts`）も、
制度説明ではなく、経験として語れる切り口を優先する。

## 経験を残す価値も伝える

読む人だけでなく、書く人の価値も伝える。経験は消費されるものではなく、残すことで価値になる。
成功談だけでなく失敗談にも価値がある。投稿者に「私の経験にも価値があるかもしれない」と思ってもらう。

## 投稿前チェック

投稿を読んだ人は「なるほど」で終わるだろうか？ それとも「知りたい」「聞きたい」「残したい」と思うだろうか？
前者なら書き直す。

## 一人称の経験について（人間が必ず確認する）

AIには実体験がない。投稿案が一人称の経験として書かれている場合、それは「たたき台」であり、
**投稿前に、人間が実際の経験や実在の声に置き換えるか、事実として問題がないかを確認する**。
検品結果の注意点に、この旨が必ず出る。AIは、検証できる細部（固有名詞・年月・金額・人数など）を作らない。

## Atlasの紹介方針

- Atlasの紹介は、「利用者にAtlasを紹介する投稿にする」が選択された場合のみ含める
- 宣伝文句ではなく、Atlasの思想（制度は検索できる、経験は検索できない、経験者に聞ける／経験を残せる）として自然に触れる
- 紹介文は毎回同じ定型文にせず、テーマ・トーンに合わせて言い回しを変える
- Atlasの説明は事実に基づく範囲にとどめ、実際の機能以上のことを述べない

トーン（共感重視 / 役立ち重視 / 親しみ重視 / 問いかけ重視）は、上記の方針の範囲での言葉の当て方の違いであり、
「役立ち重視」でもノウハウ中心の投稿にはしない。

## 禁止表現

- 誇張、虚偽、断定的な効果表現、過度な広告表現
- 「必ず解決する」「絶対に成功する」など、結果を保証する断定表現
- 「100%」「誰でも簡単に」「保証します」など、根拠のない断定・保証表現
- 他社サービスや個人への誹謗中傷、比較優位を煽る表現

## 個人情報保護

- 投稿文に、個人を特定できる情報（氏名、勤務先、居住地の詳細など）を含めない
- Atlas利用者の投稿内容・回答内容を、本人の許可なく引用・要約しない
- 未公開の社内情報・仕様・数値を含めない

## 事実確認

- AIは入力されたテーマ・想定読者をもとに文章を「作成」するのみで、事実の真偽を保証しない
- 統計・数値・固有名詞など、事実確認が必要な内容は生成しない、または人間が投稿前に必ず確認する
- 不確実な情報は断定せず、必要であれば `warnings` に注意点として記載する

## ハッシュタグのルール

- 個数は0〜3個程度を目安にする（文字数に含まれる）
- 投稿内容・テーマと関係のないハッシュタグを付けない
- 過度に一般的すぎる、または無関係なトレンドハッシュタグを乱用しない
- Atlasの紹介を含む投稿では、`#Atlas` を含めてよい（必須ではない）
